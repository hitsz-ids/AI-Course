# 如何使用RA的方式来进行量化交易

一个典型的数据驱动任务Research流程为：

1. 梳理任务SoW (Statement of Work)，包括任务简介、任务Benchmark（训练集和测试集）、测评指标和脚本等；
2. 综述完成任务相关工作，对现有技术进行分类；
3. 实验筛选，将检索到的相关工作在已有任务Benchmark上进行适配和复现，选出效果最佳的工作；
4. 在已有工作上进行优化以进一步提升方案性能。

```YAML
你是一位顶尖的科普作家和知识转述者，被誉为“最会搭梯子的人”。你的专长是将那些充斥着术语、数据和复杂模型的学术论文，转译（Reframe）成普通大众能轻松读懂、产生共鸣并深受启发的科普文章。

你的使命不是“翻译”论文，而是“重建”理解。你为读者搭建一座从“一无所知”到“原来如此”的桥梁，让他们在零负担的阅读中，领略到科学研究的真正魅力、核心发现及其对现实世界的意义。

工作流程：从论文到科普的“阶梯搭建”

当你收到一篇需要进行科普解读的学术论文时，你将严格遵循以下步骤：

* 第一步：挖掘“人”与“动机” (The "Who" and "Why")

  * 在深入论文细节前，先检索作者及其所属机构的背景。
  * 尝试建立一个有趣的联系：为什么是“他们”在研究“这个”问题？
    （例如：这个实验室是否一直在该领域深耕？他们是不是“跨界”解决了一个老问题？或者这个机构的使命是否与此相关？）
  * 【应用规则】：如果背景故事（如作者的“执念”或机构的“使命”）能让研究动机更生动，就在文章中巧妙融入。
    如果联系牵强，则不必在正文中提及，避免生硬介绍。

* 第二步：钻研与消化 (Digest and Understand)

  * 深入阅读论文，彻底拆解其核心三要素：

    1. 研究问题 (The Question)：他们到底想解决什么谜题？这个问题的背景和重要性是什么？
    2. 研究方法 (The How)：他们是怎么找到答案的？（重点理解其思路，而非复述技术细节）
    3. 核心发现 (The Finding)：他们最终发现了什么？这个发现有多“反直觉”或多“重要”？

* 第三步：定位“行业坐标”与“Aha!时刻” (Locate its Position and the "Aha! Moment")

* （必要时使用工具检索）结合业界或学术界的现状来分析这篇论文。
  * 它在整个领域中扮演了什么角色？是解决了同行一个“老大难”的痛点？是推翻了一个旧认知？还是开辟了一个全新的赛道？
  * 提炼“故事线”：将论文的“论证逻辑”转化为“叙事逻辑”。
    找到论文中最激动人心的“Aha!”时刻，并明确这篇科普文章的核心“卖点”（Takeaway）——读者读完后，能带走的那个最清晰、最有价值的知识点。

* 第四步：撰写科普博文 (Compose the Pop-Science Blog)

  * 完全代入下方定义的“角色定位”与“写作风格”，撰写一篇独立、完整、引人入胜的科普解读。
  * 注意：篇幅长度不限，以“把普通人彻底讲明白”为唯一标准。
  * 确保在“所以呢？” (The "So What?") 部分，有力地传达出它对行业或普通人的真正影响（基于第三步的分析）。

---

读者与风格

* 目标读者：对世界充满好奇的普通大众。他们没有专业背景，渴望理解新知识，但对术语和公式天然“过敏”。他们阅读的目的是获取新知、满足好奇心和“哇塞”的瞬间。
* 写作风格：

  * 极致通俗 (Radical Accessibility)：比喻是你的第一语言。能用“厨房里的化学反应”解释的，绝不用“非对映选择性”。如果必须使用术语，必须立刻用一个生动的类比将其“翻译”掉。
  * 故事为王 (Storytelling)：把研究过程讲成一个“破案故事”或“探险之旅”。科学家是主角，他们面临一个难题，设计了一个聪明的“陷阱”（实验），最后抓住了“真相”（结论）。
  * 聚焦“所以呢？” (The "So What?")：时刻帮读者回答这个问题。这个研究跟我有什么关系？它为什么重要？它可能如何改变我们的生活或认知？
  * 简化而不歪曲 (Simplify, Don't Misrepresent)：这是科普的底线。在简化复杂概念时，保持核心事实的准确性。清晰地区分“已证实的”和“推测的”。

---
写作思路与技巧（供自由使用）

* 开篇点题，建立框架：

  * 可以用一个生动的问题、反直觉的观察或核心冲突来引入主题，快速帮读者定位。
  * 也可以先用简洁的语言勾勒出原文要解决的核心问题或讨论范围。

* 结构化梳理，逐层解析：

  * 善用小标题或清晰的段落划分，引导读者逐步理解。
  * 在转述原文观点时，无缝融入类比，让复杂的点变得具体可感。（例如：“作者提到的‘异步通信’，你就可以理解为发邮件，而不是打电话。”）

* 聚焦重点，详略得当：

  * 明确区分主干与枝叶。重点阐释核心观点与关键逻辑，简略带过次要信息。
  * 确保读者高效抓住重点。

* 巧妙融入背景：

  * 如果原文涉及人物或机构背景，自然融入解读，帮助读者理解“为什么”或“此刻的重要性”，避免生硬介绍。

* 结尾总结，提供价值：

  * 清晰提炼原文核心价值，或指出其当下意义。
  * 给读者一个明确的Takeaway，让他们确实学到东西，理解原文。

---

禁止出现的表达方式

* 避免生硬的引导语，如“本文研究了……”、“该论文的作者发现……”、“实验结果表明……”。
* 严禁直接复制论文摘要或引言中的学术黑话。
* 避免罗列枯燥数据或统计指标（如p值、置信区间），除非能转译为“有多大把握”或“效果有多明显”。

---

核心目标

你的文字是读者通往科学殿堂的“快速通道”和“专属翻译器”。
你必须用最大的真诚和智慧，将学术的“硬核”包裹在通俗、有趣、有故事性的“糖衣”里，让读者在愉快的阅读中，毫不费力地吸收最前沿的知识精髓。
```

~~~YAML
展示：

* 股票维度：N 只股票
* 时间维度：T 个交易日
* 特征维度：F 个特征

用简化形式表示：

X ∈ R^(N × T × F)

说明：

* 对每只股票，模型看过去 T 天。
* 每天有 F 个特征。
* 最终输入不是一行表，而是一个三维数据块。

Canvas 表现：

* 把表格转成多个小矩阵。
* 每只股票一个 T × F 的特征矩阵。
* 用堆叠效果表示 N 只股票。

---

### Step 3：时间维度上，模型学习单只股票自己的节奏

解释：

* 模型先看一只股票过去几天的变化。
* 它学习的是“这只股票自己的走势节奏”，例如动量是否延续、波动是否放大、成交量是否异常。

简化公式：

h_i = TemporalEncoder(X_i)

或如果论文有具体公式，优先使用论文公式。

Canvas 表现：

* 画一只股票的时间序列。
* 用不同深浅显示不同日期的权重。
* 右侧输出该股票的时间表示 h_i。

必须展示一个可复盘数字例子，例如：

h_茅台 = 0.5 × Day1 + 0.3 × Day2 + 0.2 × Day3

---

### Step 4：横截面上，模型学习股票之间的相对关系

解释：

* 投资里选股不是只问“这只股票好不好”。
* 更重要的是“它相对其他股票是否更好”。
* 所以模型需要比较股票之间的关系。

简化公式：

s_ij = similarity(h_i, h_j)

或论文中的注意力、图结构、相关性公式。

Canvas 表现：

* 画多个股票节点。
* 节点之间用线连接。
* 线越粗表示关系越强。
* 旁边显示一个关系矩阵。

必须展示一个可复盘数字例子，例如：

关系矩阵 A：

|      |   茅台 | 宁德时代 | 东方财富 |
| ---- | ---: | ---: | ---: |
| 茅台   | 1.00 | 0.32 | 0.18 |
| 宁德时代 | 0.32 | 1.00 | 0.64 |
| 东方财富 | 0.18 | 0.64 | 1.00 |

### Step 5：市场状态或动态权重如何影响模型判断

如果论文包含市场状态、动态注意力、门控机制、状态切换、因子权重变化，必须解释这一部分。

说明：

* 牛市、震荡市、下跌市中，有效因子可能不同。
* 模型通过动态权重或状态变量调整关注点。

简化公式：

z_i = α_market × h_i + α_relation × relational_i

Canvas 表现：

* 左侧显示市场状态，例如“震荡市”。
* 中间显示不同因子的权重条。
* 右侧显示加权后的股票表示。

如果论文没有市场状态模块，则改成论文真实的核心模块，不要强行加入。

### Step 6：输出预测分数并排序

解释：

* 模型最终输出的通常不是“绝对能涨多少”，而是一个用于排序的分数。
* 分数越高，代表模型认为未来相对表现越好。

简化公式：

score_i = MLP(z_i)

或论文真实输出层公式。

Canvas 表现：

* 显示每只股票的预测分数。
* 画柱状图。
* 按分数排序。
* 高亮 Top K 股票。

示例：

| 股票   | 预测分数 | 排名 |
| ---- | ---: | -: |
| 东方财富 | 0.82 |  1 |
| 茅台   | 0.61 |  2 |
| 宁德时代 | 0.47 |  3 |

### Step 7：训练时模型如何知道自己错了

解释：

* 训练时，模型会把预测排序和未来真实收益排序比较。
* 如果预测错了，就通过损失函数调整参数。

简化公式：

Loss = RankingLoss(score, future_return)

或论文真实损失函数。

Canvas 表现：

* 左侧显示预测排名。
* 右侧显示未来真实收益排名。
* 用红色标出错位。
* 显示损失值下降的简单曲线。

必须说明：

* 训练阶段能看到未来标签。
* 推理阶段不能看到未来，只能用历史数据预测。
~~~

### 论文理解

##### 1.我们要知道论文到底讲了什么思想

cline对话框输入prompt让大模型将论文解读一下,我们需要知道论文到底讲了什么思想

```YAML
你是一位顶尖的科普作家和知识转述者，被誉为“最会搭梯子的人”。你的专长是将那些充斥着术语、数据和复杂模型的学术论文，转译（Reframe）成普通大众能轻松读懂、产生共鸣并深受启发的科普文章。

你的使命不是“翻译”论文，而是“重建”理解。你为读者搭建一座从“一无所知”到“原来如此”的桥梁，让他们在零负担的阅读中，领略到科学研究的真正魅力、核心发现及其对现实世界的意义。

---

工作流程：从论文到科普的“阶梯搭建”

当你收到一篇需要进行科普解读的学术论文时，你将严格遵循以下步骤：

* 第一步：挖掘“人”与“动机” (The "Who" and "Why")

  * 在深入论文细节前，先检索作者及其所属机构的背景。
  * 尝试建立一个有趣的联系：为什么是“他们”在研究“这个”问题？
    （例如：这个实验室是否一直在该领域深耕？他们是不是“跨界”解决了一个老问题？或者这个机构的使命是否与此相关？）
  * 【应用规则】：如果背景故事（如作者的“执念”或机构的“使命”）能让研究动机更生动，就在文章中巧妙融入。
    如果联系牵强，则不必在正文中提及，避免生硬介绍。

* 第二步：钻研与消化 (Digest and Understand)

  * 深入阅读论文，彻底拆解其核心三要素：

    1. 研究问题 (The Question)：他们到底想解决什么谜题？这个问题的背景和重要性是什么？
    2. 研究方法 (The How)：他们是怎么找到答案的？（重点理解其思路，而非复述技术细节）
    3. 核心发现 (The Finding)：他们最终发现了什么？这个发现有多“反直觉”或多“重要”？

* 第三步：定位“行业坐标”与“Aha!时刻” (Locate its Position and the "Aha! Moment")

* （必要时使用工具检索）结合业界或学术界的现状来分析这篇论文。
  * 它在整个领域中扮演了什么角色？是解决了同行一个“老大难”的痛点？是推翻了一个旧认知？还是开辟了一个全新的赛道？
  * 提炼“故事线”：将论文的“论证逻辑”转化为“叙事逻辑”。
    找到论文中最激动人心的“Aha!”时刻，并明确这篇科普文章的核心“卖点”（Takeaway）——读者读完后，能带走的那个最清晰、最有价值的知识点。

* 第四步：撰写科普博文 (Compose the Pop-Science Blog)

  * 完全代入下方定义的“角色定位”与“写作风格”，撰写一篇独立、完整、引人入胜的科普解读。
  * 注意：篇幅长度不限，以“把普通人彻底讲明白”为唯一标准。
  * 确保在“所以呢？” (The "So What?") 部分，有力地传达出它对行业或普通人的真正影响（基于第三步的分析）。

读者与风格

* 目标读者：对世界充满好奇的普通大众。他们没有专业背景，渴望理解新知识，但对术语和公式天然“过敏”。他们阅读的目的是获取新知、满足好奇心和“哇塞”的瞬间。
* 写作风格：

  * 极致通俗 (Radical Accessibility)：比喻是你的第一语言。能用“厨房里的化学反应”解释的，绝不用“非对映选择性”。如果必须使用术语，必须立刻用一个生动的类比将其“翻译”掉。
  * 故事为王 (Storytelling)：把研究过程讲成一个“破案故事”或“探险之旅”。科学家是主角，他们面临一个难题，设计了一个聪明的“陷阱”（实验），最后抓住了“真相”（结论）。
  * 聚焦“所以呢？” (The "So What?")：时刻帮读者回答这个问题。这个研究跟我有什么关系？它为什么重要？它可能如何改变我们的生活或认知？
  * 简化而不歪曲 (Simplify, Don't Misrepresent)：这是科普的底线。在简化复杂概念时，保持核心事实的准确性。清晰地区分“已证实的”和“推测的”。

---
写作思路与技巧（供自由使用）

* 开篇点题，建立框架：

  * 可以用一个生动的问题、反直觉的观察或核心冲突来引入主题，快速帮读者定位。
  * 也可以先用简洁的语言勾勒出原文要解决的核心问题或讨论范围。

* 结构化梳理，逐层解析：

  * 善用小标题或清晰的段落划分，引导读者逐步理解。
  * 在转述原文观点时，无缝融入类比，让复杂的点变得具体可感。（例如：“作者提到的‘异步通信’，你就可以理解为发邮件，而不是打电话。”）

* 聚焦重点，详略得当：

  * 明确区分主干与枝叶。重点阐释核心观点与关键逻辑，简略带过次要信息。
  * 确保读者高效抓住重点。

* 巧妙融入背景：

  * 如果原文涉及人物或机构背景，自然融入解读，帮助读者理解“为什么”或“此刻的重要性”，避免生硬介绍。

* 结尾总结，提供价值：

  * 清晰提炼原文核心价值，或指出其当下意义。
  * 给读者一个明确的Takeaway，让他们确实学到东西，理解原文。

---

禁止出现的表达方式

* 避免生硬的引导语，如“本文研究了……”、“该论文的作者发现……”、“实验结果表明……”。
* 严禁直接复制论文摘要或引言中的学术黑话。
* 避免罗列枯燥数据或统计指标（如p值、置信区间），除非能转译为“有多大把握”或“效果有多明显”。
```

~~~YAML
## 模块 3 推荐动画步骤

请优先使用以下流程。如果论文结构不同，可以根据论文机制调整，但仍需保持“原始数据 → 特征 → 模型输入 → 学习 → 推理 → 排序”的逻辑。

### Step 1：从人能看懂的原始股票数据开始

展示一个小表格，例如：

| 股票   |  过去收益 | 成交量变化 |  波动率 | 估值因子 |
| ---- | ----: | ----: | ---: | ---: |
| 茅台   |  2.1% |    5% | 1.2% |  0.8 |
| 宁德时代 | -1.3% |   12% | 2.4% |  1.1 |
| 东方财富 |  3.2% |   18% | 3.1% |  1.5 |

说明：

* 这是原始可观察数据。
* 模型不是直接“猜涨跌”，而是先把股票转成特征向量。

Canvas 表现：

* 画一个数据表。
* 高亮每只股票的一行。
* 右侧显示该股票对应的特征向量。

---

### Step 2：构造模型输入矩阵或张量

展示：

* 股票维度：N 只股票
* 时间维度：T 个交易日
* 特征维度：F 个特征

用简化形式表示：

X ∈ R^(N × T × F)

说明：

* 对每只股票，模型看过去 T 天。
* 每天有 F 个特征。
* 最终输入不是一行表，而是一个三维数据块。

Canvas 表现：

* 把表格转成多个小矩阵。
* 每只股票一个 T × F 的特征矩阵。
* 用堆叠效果表示 N 只股票。

---

### Step 3：时间维度上，模型学习单只股票自己的节奏

解释：

* 模型先看一只股票过去几天的变化。
* 它学习的是“这只股票自己的走势节奏”，例如动量是否延续、波动是否放大、成交量是否异常。

简化公式：

h_i = TemporalEncoder(X_i)

或如果论文有具体公式，优先使用论文公式。

Canvas 表现：

* 画一只股票的时间序列。
* 用不同深浅显示不同日期的权重。
* 右侧输出该股票的时间表示 h_i。

必须展示一个可复盘数字例子，例如：

h_茅台 = 0.5 × Day1 + 0.3 × Day2 + 0.2 × Day3

---

### Step 4：横截面上，模型学习股票之间的相对关系

解释：

* 投资里选股不是只问“这只股票好不好”。
* 更重要的是“它相对其他股票是否更好”。
* 所以模型需要比较股票之间的关系。

简化公式：

s_ij = similarity(h_i, h_j)

或论文中的注意力、图结构、相关性公式。

Canvas 表现：

* 画多个股票节点。
* 节点之间用线连接。
* 线越粗表示关系越强。
* 旁边显示一个关系矩阵。

必须展示一个可复盘数字例子，例如：

关系矩阵 A：

|      |   茅台 | 宁德时代 | 东方财富 |
| ---- | ---: | ---: | ---: |
| 茅台   | 1.00 | 0.32 | 0.18 |
| 宁德时代 | 0.32 | 1.00 | 0.64 |
| 东方财富 | 0.18 | 0.64 | 1.00 |

---

### Step 5：市场状态或动态权重如何影响模型判断

如果论文包含市场状态、动态注意力、门控机制、状态切换、因子权重变化，必须解释这一部分。

说明：

* 牛市、震荡市、下跌市中，有效因子可能不同。
* 模型通过动态权重或状态变量调整关注点。

简化公式：

z_i = α_market × h_i + α_relation × relational_i

Canvas 表现：

* 左侧显示市场状态，例如“震荡市”。
* 中间显示不同因子的权重条。
* 右侧显示加权后的股票表示。

如果论文没有市场状态模块，则改成论文真实的核心模块，不要强行加入。

---

### Step 6：输出预测分数并排序

解释：

* 模型最终输出的通常不是“绝对能涨多少”，而是一个用于排序的分数。
* 分数越高，代表模型认为未来相对表现越好。

简化公式：

score_i = MLP(z_i)

或论文真实输出层公式。

Canvas 表现：

* 显示每只股票的预测分数。
* 画柱状图。
* 按分数排序。
* 高亮 Top K 股票。

示例：

| 股票   | 预测分数 | 排名 |
| ---- | ---: | -: |
| 东方财富 | 0.82 |  1 |
| 茅台   | 0.61 |  2 |
| 宁德时代 | 0.47 |  3 |

---

### Step 7：训练时模型如何知道自己错了

解释：

* 训练时，模型会把预测排序和未来真实收益排序比较。
* 如果预测错了，就通过损失函数调整参数。

简化公式：

Loss = RankingLoss(score, future_return)

或论文真实损失函数。

Canvas 表现：

* 左侧显示预测排名。
* 右侧显示未来真实收益排名。
* 用红色标出错位。
* 显示损失值下降的简单曲线。

必须说明：

* 训练阶段能看到未来标签。
* 推理阶段不能看到未来，只能用历史数据预测。
~~~

1. ##### 传统Vibe Coding在做什么？

Vibe Coding主流的两种思路:

1. ##### 我们的方法:  群体智能+基于第一性原理的领域边界契约模式

**群体智能****:**

我们不自己创造核心算法，而是去搜罗公开的、已发表的Sota工作（如金融数据处理开源库、因子挖掘框架、回测引擎等），让AI理解它们、调用它们、组合它们.

**基于****第一性原理****的领域边界契约模式:**

**基于****第一性原理****的领域专用边界契约模式**.**AI负责根据契约编写代码,同时生成边界契约检查代码,我们只需要看代码能否通过边界契约检查就行,而不用去看繁琐的代码.**

1. #### 群体智能+边界契约模式在金融量化任务上如何**?**

传统的Vibe Coding在适配任务上会自动补全一个它认为“合理”的方案——通常是训练数据中出现频率最高的方案.

但是在金融量化任务上,如果让AI自由发挥,就会造成看似结果好看,但是不可用的问题:比如**未来数据泄露**,**标签污染**、**样本身份破坏**等问题.

如何使用我们的方法来完成金融量化任务?

金融量化领域,常见的关键的边界有: 1.禁止使用未来数据 2.训练数据集,验证数据集,测试数据集禁止时间交叉.

我们认为在适配任务上,最重要的环节是**数据适配**与**算法适配.** 结合我们提出的第一性原理边界契约,总结了如下边界契约

##### 1.核心原则 

- 绝对底线：模型所发出的最终信号（预测、分数、投资组合），只能使用信号时刻可观测到的信息
- 严禁目标污染信号：目标值（标签）可以用于训练和计算评估指标，但绝对不允许以任何形式渗透进最终的预测信号中 
- 事实为准：源码和论文是理解意图的线索，但当前运行的代码、生成的工件和评估器的实际输出才是需要审查的最终真相

##### 2.数据边界 

- 官方划分/评估器: 数据切分必须严格遵循官方基准
- 标签期限: 目标必须代表预期的未来结果和期限
- 时间可观测性: 确保每个特征在信号时刻都是可观测的（无未来信息）
- 拟合范围: 数据变换（标准化等）只能拟合于训练集
- 特征/上下文构建: 确保模型输入包含正确的字段、顺序和缺失值处理
- 样本身份: 确保行/实体/时间/图的身份在流程中不被篡改
- 工件消费者交接: 生产的工件必须符合算法加载器的合约（形状/类型）
- 训练候选队列: 不预判性能，完整枚举可运行的训练策略

##### 3.算法边界

- 任务输出: 确保最终提交给评估器的预测/分数格式正确
- 样本身份: 确保模型输入、标签、预测、评估行指向同一个具体样本 
- 批次交互: 确保批次分组符合模型/损失函数对组内交互的要求
- 训练目标/目标路径: 明确损失函数如何消费预测、目标、权重、掩码，且目标不污染信号
- 预测信号路径: 输出具有正确样本身份的、非恒定的有限分数
- 目标消费型指标路径: 安全地使用标签计算指标，不污染信号
- 检查点策略: 确保保存/加载的模型状态符合指定的选型规则
- 可疑信号: 发现异常（如早早停止、指标异常高）时，触发重新审计

按照我们的思路使用群体智能方式: 对于缺失的数据处理部分,我们通过使用DeepRearch检索AI在金融任务上如何处理数据的相关工作,经过筛选后选了以下几篇:

- [1] Arian H, Norouzi Mobarekeh D, Seco L. Backtest overfitting in the machine learning era: A comparison of out-of-sample testing methods in a synthetic controlled environment[J]. Knowledge-Based Systems, 2024, 305: 112477. https://doi.org/10.1016/j.knosys.2024.112477

这几篇相关工作中提到金融任务下的数据的重点:

1. 金融任务下机器学习归一化,交叉验证与重训练使用未来数据会导致alpha失效
2. 金融任务要有专门的验证方案.

根据论文提到的重点,我们总结出在金融量化任务上,数据处理时需要注意以下特点:

**1.时间点对齐**

任意决策时刻t所使用的每一个特征，必须在时刻t或之前可被观测到。严格拒绝任何读取未来时间戳或未来修订版本的特征路径.

举个例子:

在训练时间范围使用到了未来数据,就会导致回测时表现惊艳，实盘交易时一塌糊涂——因为你的模型在回测中使用了未来信息，而那些信息在真实交易中根本不存在。这是量化研究中最常见的“自杀式错误”

**2.缺失值处理**

在金融数据中, 停牌、休市、涨跌停、数据故障等原因导致缺失值普遍存在,在数据处理中要对缺失值进行处理.

缺失值填充仅限于在同一个实体（Entity，如某一只股票）维度上进行因果前向填充（Forward Fill）——即用同一只股票过去有效交易日的数据来补现在的缺失。禁止后向填充（Backward Fill）会导致数据泄露。

举个例子: 

股票日期t停牌,对t交易日进行填充的时候,只能用前一个有效交易日的数据,而不能把未来数据填充过来,使用T+1日的数据就会造成数据泄露.

**3.缺失值处理数据时效性约束**

用过去的值填充现在的缺失值，不能无限期有效——超过一定时间（TTL）就失效了，必须标记或剔除。

举个例子:

某只股票已经退市了，但数据上没有明确标记。按照前向填充规则，它的价格一直停留在最后一个有效交易日的数据上。如果你不设TTL约束，这个退市股票会一直存在于你的训练样本中，模型学到的可能是“这支股票价格永远不变”的错误模式.同时，它在回测中会贡献虚假的“交易信号”和“收益”，污染整个模型评估结果.

**4.时序安全切分**

必须采用基于时间顺序的切分语义；严格防止因切分边界跨越而导致的“标签窗口重叠”式数据泄露。

金融数据是时间序列，样本之间存在严格的先后依赖关系。如果切分时有交叉，训练时就会用到“未来”的信息来预测“过去”.

从我们的benchmark中就可以看到:训练集,验证集,测试集的时间范围是不能有交叉的.

### 总结

我们的方法群体智能+基于第一性原理的领域边界契约模式定位:

我们不教AI怎么“思考”（CoT），也不给AI设计“执行流程”（Workflow），而是让AI去“搜罗公开的相关工作”组合适配，同时用“边界契约”来验收结果——通过就是通过，不通过就重来

方法的两层架构:

**第一层：****群体智能**

在Master论文中,核心的数据源代码处理并没有公开,我们通过检索金融数据处理相关工作，总结出金融数据处理的第一性原理与边界.

**第二层：基于****第一性原理****的领域边界契约模式**

AI负责根据契约编写代码，同时生成边界契约检查代码，我们只需要看核心代码是否正确,以及代码能否通过边界契约检查——而不用去看繁琐的核心代码.

## 指标

1. IC

IC 衡量预测信号在**数值层面**对未来收益的线性预测能力。

| IC               | 解释                       |
| :--------------- | :------------------------- |
| IC < 0           | 预测方向错误，需要检查模型 |
| IC < 0.02        | 预测能力较弱               |
| 0.02 ≤ IC < 0.05 | 具有一定预测能力           |
| IC ≥ 0.05        | 预测能力较为显著           |

1. ICIR

衡量预测信息在时间维度上的稳定性与统计显著性

| ICIR               | 解释                           |
| :----------------- | :----------------------------- |
| ICIR < 0.30        | 预测信息不稳定，统计显著性不足 |
| 0.30 ≤ ICIR < 0.50 | 预测信息具有一定稳定性         |
| ICIR ≥ 0.50        | 预测信息稳定且具有统计显著性   |

1. Rank IC

衡量预测信号在**排序层面**区分未来收益高低的能力，不依赖于数值尺度。（实际中很多时候关心的是股票的相对强弱，通过排名来选股。）

| Rank IC                   | 解释             |
| :------------------------ | :--------------- |
| \|Rank IC\| < 0.02        | 排序能力较弱     |
| 0.02 ≤ \|Rank IC\| < 0.05 | 具有一定排序能力 |
| \|Rank IC\| ≥ 0.05        | 排序能力较为显著 |

1. ICIR

Rank ICIR 反映预测信号排序能力是否在不同时间段内保持一致。

| ICIR               | 解释                         |
| :----------------- | :--------------------------- |
| ICIR < 0.30        | 排序能力不稳定               |
| 0.30 ≤ ICIR < 0.50 | 排序能力具有一定稳定性       |
| ICIR ≥ 0.50        | 排序能力稳定且具有统计显著性 |
